# PRペアレビュースキル

## 役割
他人の PR を、**人間と一緒に**ファイルごとに読み進める。指摘は人間の承認を得てから投稿する。

自分の PR に付いたコメントへの対応は `/resolve-comments`、自分の実装のレビューは `/review`。このスキルは**他人の PR を読む側**専用。

## 入出力
- **入力**: PR 番号（引数、または人間に確認）と `gh pr diff` の差分
- **出力**: ファイル成果物は持たない（GitHub 上のコメントが成果）

## モード
**ペアレビューは対話そのもの**なので、人と一緒に読み進める前提で動く。

このスキルは**人に聞くのが仕事**である（読み進める速度も、指摘するかどうかも人と決める）。

## 進め方

### Step 1: 対象 PR の特定
引数に PR 番号があればそれを使う。無ければ人間に確認する。

```
gh pr view <PR番号> --json number,title,url,author
```

特定できなければ中断する。

### Step 2: 差分の取得

```
gh pr diff <PR番号>
```

差分をファイル単位に分け、レビューする順序（関連の強いファイルをまとめる）を決める。

### Step 3: ファイルごとに読む
ファイルごとに差分を提示しながら人間と一緒に読み、気になる点があればその場で議論する。

- **一度に全ファイルを流さない**。1 ファイルずつ、人間が読み終わるのを待って進める
- 指摘が必要と判断したら**コメント文を作成して人間に確認する**（文面の承認を得るまで投稿しない）

### Step 4: コメントの投稿
承認されたコメントだけを投稿する：

```
gh pr comment <PR番号> --body "<コメント内容>"
```

投稿は**外向きの発信**なので、承認されていない文面を勝手に出さない。

### Step 5: 出力

次の完了カードを、コードフェンス自体は出さずに中身だけそのまま出力して終了する。
カードの前後に作業サマリ・所感・補足を足さない。

```markdown
### PR ペアレビュー完了
<対象 PR とレビュー範囲を 1 行>
- <主要な結果 最大 3 行>

生成物: `<レビュー対象 PR の URL>`

### 要確認
- <読んだが判断を保留した点>（該当: <ファイル:行>）

### 次の一手
- レビュー結果を PR で伝える（停止点）
```

カードは**やったこと**・**要確認**・**次の一手**の 3 ブロックに分ける。混ぜない。

- やったこと: 一言サマリは 1 行。主要な結果は `- ` の箇条書きで**最大 3 行**（レビューしたファイル数・投稿したコメント件数・要注意の論点など。無ければ行ごと省略）。指摘の本文は PR のコメントに寄せ、カードには列挙しない。ファイル成果物を持たないので生成物の行にレビュー対象 PR の URL を出す。
- 要確認: 気になったがコメントにはしなかった点、判断がつかず保留した点を挙げる。無ければブロックごと省略する。
- 次の一手: ここは停止点なので 1 行に留める。

**中断時**: ヘッダを `### PR ペアレビュー中断` に差し替え、一言サマリに中断理由（PR を特定できない・差分を取得できないなど）、次の一手に復帰コマンドを書く。

## 完了条件
全差分ファイルを人間と読み終え、承認された指摘の投稿まで済ませたら完了（指摘が 0 件でも完了）。
