# 種文書起票スキル

## 役割
チャットで固まった要望を受け取り、feature 名を決めて `.specs/<feature>/seed.md` を書き出す。
まだ `.specs/` に何も無い最初の一歩を受け止め、`/spec` に引き継ぐ。

## 入出力
- **入力**: `$ARGUMENTS[0]`（任意、希望 feature 名）/ 直前までの会話で固まった要望
- **出力**: `.specs/<feature>/seed.md`

## 対話方針
**非対話**: 要件詳細化のための質問やスコープ承認はしない。
feature 名の命名・別名採番・テンプレート項目の埋め方など判断が割れる点は、最も素直な解釈を採って自分で確定する
（無確認実行）。
確定できなかった内容は seed.md 側に「TODO: /spec で詳細化」として残す。

## 進め方

### Step 1: 引数チェック
- `$ARGUMENTS[0]`（任意、希望 feature 名）を読む
- 会話文脈から、チャットで固まった要望を読む

**完了ゲート:** 引数・要望それぞれの有無を確認したか。

### Step 2: 要望の特定
- 引数もチャット文脈の要望も無ければ「使い方: /seed [要望]」を表示して終了する
- どちらか一方でもあれば Step 3 へ進む

**完了ゲート:** 要望の実体が特定できたか（無ければ Step 1〜2 で終了しているはず）。

### Step 3: feature 名決定・衝突チェック・別名採番

- `$ARGUMENTS[0]` があれば kebab-case・3〜5 語程度に正規化し、そのまま候補にする
- 無ければ要望テキストから同じ制約で kebab-case・3〜5 語程度の候補を生成する
- `Glob(".specs/*")` で既存 feature を列挙し、候補と衝突するか確認する
- 衝突するときは、衝突を理由に中断せず区別できる別名を自動で採番する（末尾に連番や
  区別可能な語を足す）。
  ユーザーに確認しない

**完了ゲート:** 既存 `.specs/` と衝突しない feature 名を確定したか。

### Step 4: seed.md の書き出し

要望から埋められない項目には「TODO: /spec で詳細化」と明記する。
質問で埋めない。

**【異常】** 要望が実質的に空で、次のテンプレートの主要項目を 1 つも埋められないときは
書き出さずに中断し、Step 5 で理由を報告する。

`.specs/<feature>/seed.md` に次のテンプレートで書く:

```markdown
# <タイトル: 何をしたい変更か 1 行で>

## 背景・目的
なぜこの変更が要るか。専門用語・内部用語は本文で説明する。

## やりたいこと
何を実現したいか。挙動・体験のレベルで書く（実装方法は指定しない）。

## 対象範囲・既知の手がかり
実コードで確認した対象ファイルや該当箇所（参考情報。詳細化の起点）。
不足している情報は「TODO: /spec で詳細化」と明記し、質問で埋めない。

## 制約・前提
外せない条件、やってほしくないこと、既存仕様との整合など。

## 拾い方
この種文書は未着手。`/spec <新feature>` を実行して requirements 詳細化から始める。
```

**完了ゲート:** `.specs/<feature>/seed.md` を Write したか（中断時は Write していないか）。

### Step 5: 出力

次の完了カードを、コードフェンス自体は出さずに中身だけそのまま出力して終了する。
カードの前後に作業サマリ・所感・補足を足さない。
`/spec` は自動起動せずユーザーの実行を待つ。

```markdown
### 種文書起票完了
<何を起票したかを 1 行>
- <主要な結果 最大 3 行>

生成物: `.specs/<feature>/seed.md`

### 次の一手
- 要件に落とす: `/spec <feature>`
```

**中断時**: ヘッダを `### 種文書起票中断` に差し替え、一言サマリに中断理由（要望が無い・
主要項目を埋められないなど）を書く。
生成物の行は省略する。

```markdown
### 種文書起票中断
<中断理由を 1 行>

### 次の一手
- 要望を添えてやり直す: `/seed [要望]`
```

## 完了条件
feature 名を決定し `.specs/<feature>/seed.md` を Write したか、要望不足で中断カードを
出したかのいずれかで終わっていれば完了。
次工程の起動は完了条件に含めない。
