# 提案キュー棚卸しスキル

## 役割
`.specs/proposals/` に積み上がった提案を 1 コマンドで走査し、**再発シグナル**（`kind: rule` の近接クラスタ）と**着手待ち一覧**（`kind: backlog`）を報告する。

**読み取り・報告・`status` 遷移だけを担う。スキル本体・`CLAUDE.md` の修正は行わない**（修正するかは人が判断する）。`/propose` が「1 件発行するだけで再発を見ない」のと対になっていて、**過去を見る役割はこちらが一手に持つ**。

提案ファイルの frontmatter スキーマの正本は `/propose` の「提案ファイルのスキーマ」。ここでは再掲しない。

## 入出力
- **入力**: `<dotfiles>/.specs/proposals/*.md`（`README.md` を除く）
- **出力**: 報告（再発シグナル / backlog 一覧）と、90 日超 singleton の `status: dropped` への更新

## モード
**手動スイープ**として人が起動する。引数は取らない。

`status: applied` への更新だけは、報告を見た人が「着手する」と判断したときに補助として提供する（対話・任意）。**明示的な指示が無い限り `applied` へは書き換えない。**

## 進め方

### Step 1: キューの解決と対象の抽出

**1-1 QUEUE_DIR**

```bash
QUEUE_DIR="$(dirname "$(dirname "$(dirname "$(readlink -f ~/.claude/skills)")")")/.specs/proposals"
```

`readlink -f` が失敗する、`QUEUE_DIR` が存在しない、中身が空（`README.md` 以外の提案ファイルが無い）場合は「提案なし」と報告して終了する。

**1-2 open な提案の抽出**

`$QUEUE_DIR/*.md`（`README.md` を除く）の frontmatter を読み、**`status: open` だけ**に絞る。`applied` / `dropped` は以降の処理から完全に除外する。

**1-3 kind の正規化**

`kind` を読み取り、次の表で 3 つの集合に分ける。**正規化はメモリ上のみで、`kind` 未指定を理由にファイルを書き換えない。**

| 読み取った `kind` | 正規化結果 |
|---|---|
| `rule` | rule 集合 |
| `backlog` | backlog 集合 |
| フィールド無し | **rule 集合**（フォールバック。既存の未指定提案を従来どおり扱うため） |
| 上記以外の値 | **不正集合**（すべての対象から外し、Step 3 でファイル名を添えて報告する） |

frontmatter が壊れている（`target` / `claim` / `date` / `status` のいずれか欠落）提案も**不正集合**に入れる（黙って無視しない）。

**完了ゲート:** rule 集合 / backlog 集合 / 不正集合の 3 つが確定したか。

### Step 2: 判定

**2-1 クラスタ検出（rule 集合のみ）**

`target` が完全一致し `claim` が近似するもの同士でグルーピングする。近似判定は AI が行う（**表現の揺れは吸収するが、無関係な claim を混ぜない**）。

- 同一クラスタが **3 件以上** → **再発シグナル**として報告対象
- 1〜2 件（singleton 含む）→ 再発として報告しない（件数の参考表示のみ）

`kind: backlog` はグルーピング・再発件数のカウントに**含めない**。

**2-2 寿命管理（rule 集合のみ）**

`date`（`YYYY-MM-DD`）を epoch に変換し、現在時刻との差が `90*86400` 秒を超えるかを判定する（macOS/BSD 前提。ロケール非依存にするため `-j -f` を使う）：

```bash
date -j -f "%Y-%m-%d" "<date>" "+%s"
now=$(date +%s)
```

- **90 日超の open singleton**（2-1 のグルーピングでクラスタを構成していないもの）だけを `status: dropped` に `Edit` で更新する
- **クラスタを構成しているメンバーは 90 日超でも drop しない**（生きた再発シグナルとして残す）
- `kind: backlog` は**経過日数に依らず drop しない**

singleton か否かは 2-1 のグルーピング結果を流用して判定する（同じ near-match ロジックを 2 度書かない）。

**完了ゲート:** クラスタが確定し、90 日超 singleton を `dropped` に更新したか。

### Step 3: 報告

明細はこのスキルの成果物そのものなので、完了カードの直前に出す（カードには件数だけを畳む）。

**再発シグナル**（rule クラスタ・3 件以上ごと）:

```
## 再発シグナル

### target: <target>
- 代表 claim: <claim>
- 件数: N
- ファイル:
  - <path1>
  - <path2>
```

クラスタが 1 つも無ければ「再発クラスタなし（open singleton のみ）」と報告する。

**backlog の別枠棚卸し**（**3 件閾値は rule 専用の概念なので backlog には適用しない。1 件から出す**）:

```
## dotfiles backlog（着手待ち）

- target: <target> ｜ <claim>
  - 発行日: <date>
  - ファイル: <path>
```

open な backlog が 1 件も無ければ「着手待ちの backlog なし」と**明示的に報告する**（節を黙って省略しない）。

不正集合があれば「不正な提案ファイルあり」としてファイル名を添えて報告する。

**完了ゲート:** 再発シグナル・backlog 一覧・不正ファイルの 3 つを（0 件でも明示して）報告したか。

### Step 4: 出力

次の完了カードを**コードフェンスで囲まず**プレーンテキストで出力して終了する。カードの後に作業サマリ・所感・補足を足さない。**スキル本体の修正は自動で行わず**ユーザーの判断を待つ。

✅ 提案キュー棚卸し完了
<走査件数と検出したクラスタ数を 1 行>
- <主要な結果 最大 3 行>
📄 .specs/proposals/<dropped に落とした提案ファイル>

要確認:
- <不正な提案ファイル>（`kind` が不正・frontmatter 欠落）

次の一手:
▶ クラスタをスキル改修に反映するか判断（停止点）

カードは**やったこと**（`✅` 〜 `📄`）・**要確認**・**次の一手**の 3 ブロックに分ける。混ぜない。

- やったこと: 一言サマリは 1 行。主要な結果は `- ` の箇条書きで**最大 3 行**（走査件数・クラスタ数・dropped 件数・backlog 件数など）。📄 行は `status` を書き換えた提案ファイルを **1 件 1 行**（更新が無ければ行ごと省略。行数上限は主要な結果にだけ課す）。
- 要確認: 不正な提案ファイルを挙げる（**すべての判定から外している**ので、放置すると永久に棚卸しされない）。無ければブロックごと省略する。
- 次の一手: 停止点なので 1 行に留める。着手すると決めたクラスタがあれば、その提案群を `status: applied` に更新する補助を提供してよい（**対話・任意。ユーザーの明示的な指示が無い限り書き換えない**。対象は rule クラスタのみ）。

**中断時**: ヘッダを `⚠ 提案キュー棚卸し中断` に差し替え、一言サマリに中断理由（`QUEUE_DIR` を解決できないなど）、次の一手に復帰コマンドを書く（更新した提案ファイルが無ければ 📄 行は省略する）。

## エラー処理
- **`QUEUE_DIR` が解決できない／空** → 「提案なし」で終了する
- **frontmatter が壊れている**（`target` / `claim` / `date` / `status` の欠落）→ すべての対象から外し、ファイル名を添えて報告する
- **`kind` の値が `rule` / `backlog` のいずれでもない** → 同様に不正扱いとし、対象から外して報告する
- **`kind` フィールドが欠落している場合だけは不正扱いにしない** → Step 1-3 の正規化に従い `rule` にフォールバックし、**ファイルは書き換えずに**従来どおり扱う

## 完了条件
- `.specs/proposals/` を 1 コマンドで走査し、rule の 3 件以上クラスタをすべて報告できた
- 90 日超の open rule singleton を `status: dropped` に更新できた（**クラスタメンバーは対象外**）
- `applied` / `dropped` がクラスタ検出の対象から除外されている
- 再発判定と寿命管理の対象が `kind: rule` に限定されている
- `kind: backlog` を別枠の一覧として報告できた（**0 件なら明示的に報告**）
- 不正な提案ファイルをすべての対象から除外し、ファイル名を添えて報告できた
