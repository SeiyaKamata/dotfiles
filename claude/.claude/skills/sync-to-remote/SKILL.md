# リモート反映スキル

## 役割
コミット後の変更を**リモートへ着地させる**。`claude/CLAUDE.md`「PR 運用の有無」の判定に従い、`あり` なら draft PR を作り、`なし` ならフェーズブランチをデフォルトブランチへ取り込んで push する。

PR を作る場合、**対象は「今いるブランチのフェーズ」1 本**。stacked 運用では base 側の PR が無いとスタック関係を表現できないため、未作成の下位フェーズがあればそれも番号順に作る。

**冪等**に作られている：既に PR があるフェーズ・既にマージ済みのブランチはスキップするので、フェーズごとに呼んでも、取りこぼしを拾うために最後にもう一度呼んでも同じ結果になる。

## 入出力
- **入力**: カレントブランチとコミット済みの差分／`.specs/<feature>/tasks.md`（PR タイトル・`着地状態:`）
- **出力**: draft PR（PR 運用あり）またはデフォルトブランチへの push（PR 運用なし）

## PR 運用の有無（吸収するのはこのスキルだけ）
**上流の工程（`/spec`〜`/commit`）はすべて PR 運用を前提に動く。** `/impl` は PR の有無に関わらず必ずフェーズブランチを切り、`/tasks` は必ず PR タイトルを発行する。運用差を吸収するのはこのスキル 1 つだけで、他の工程に分岐を持ち込まない。

判定条件・`不明` のときの倒し方は `claude/CLAUDE.md`「PR 運用の有無」に一元化してある。ここでは判定結果だけを使う：

- `あり` → Step 3-1 で draft PR を作る
- `なし` → Step 3-2 でデフォルトブランチへ取り込んで push する

## 呼ばれ方（前提）
用語は `claude/CLAUDE.md`「用語集」に従う。**フェーズ = 大タスク = ブランチ = 1 PR**。複数フェーズは stacked PR（`pN` の base は `p(N-1)`、`p1` の base はデフォルトブランチ）。

orchestrator は**フェーズループの中から**このスキルを呼ぶ（各フェーズの `/commit` 直後）。全フェーズを積んでから一斉に呼ぶ運用ではない。理由は orchestrator の「なぜフェーズごとに PR を出すのか」を参照。

## モード
**単体**: ベースブランチはデフォルトブランチを自動採用する（聞かない）。未コミットの変更があれば `/commit` を呼ぶ。

**auto（`$ARGUMENTS` に `auto` を含む）**: 完了カードを出さず 1 行の簡易ログだけ残す。未コミットの変更があれば `/commit auto` を呼ぶ。

どちらも**マージのコンフリクトと push の拒否では止まる**（自動解決は差分を壊すため）。

## 進め方

### Step 1: 前提確認

**1-1 未コミットの変更**

`git status` で確認し、あれば `/commit`（auto なら `/commit auto`）を起動して完了後に続行する。

**1-2 PR 運用の判定**

`claude/CLAUDE.md`「PR 運用の有無」に従って判定する。`不明` を安全側の `あり` に倒したときは、単体ならその判断を完了カードの「要確認」に出す。

### Step 2: 対象確定

```
DEFAULT=$(git remote show origin | grep 'HEAD branch' | awk '{print $NF}')
CURRENT=$(git branch --show-current)
```

**単一 PR か stacked か**をカレントブランチ名から判定する：

- `<feature>-pN`（末尾が `-p` + 数字）→ **stacked モード**。feature 名は `-p<数字>` を除いて求める
- それ以外（`<feature>` など）→ **単一モード**

**stacked モードでは対象を絞り込む。** 対象は「現在のフェーズ `pN`」＋「未処理の下位フェーズ `p1..p(N-1)`」だけ：

```
for i in $(seq 1 N); do
  b="<feature>-p$i"
  git rev-parse --verify "$b" >/dev/null 2>&1 || continue            # ブランチが無ければ対象外
  gh pr list --head "$b" --state all --json number --jq '.[].number'  # PR 運用あり: 空なら作成対象
  git branch --merged "$DEFAULT" | grep -qF "$b" && continue          # PR 運用なし: マージ済みなら対象外
done
```

- **`pN` より上のフェーズは対象にしない**（まだ実装されていない）
- 下位フェーズがスキップされるのは正常（フェーズループで既に処理済みのため）。結果として通常は **1 フェーズだけ**が対象になる
- 対象が 0 件 → 既存 PR の URL（PR 運用なしなら反映済みである旨）を報告して終了する

feature 名で `.specs/<feature>/tasks.md` を読み、各フェーズの **PR タイトル**と **`着地状態:`** を取得する。tasks.md が無い／未記載なら、PR タイトルはそのフェーズの最初のコミットメッセージから作る。

### Step 3: 反映

#### 3-1 PR 運用あり（draft PR を作る）

**単一モードでは、先に作業ブランチへ載せ替える。** カレントブランチがベースブランチと同じ場合、**必ず新しいブランチを作成してから PR を作る**。ブランチ名はコミット内容から自動で命名する（例: `feat/add-login`）。

```
git checkout -b <ブランチ名>
```

**この押さえが「デフォルトブランチのまま push しようとしていないか」の最終防波堤である。** `/commit` は push しないため同じ判定を持たない。push を実行するのはこのスキルなので、ここで確実にブランチへ載せ替える。既に別のブランチにいる場合はそのまま進む（stacked ではフェーズブランチが既に存在するので新規作成しない）。

利用可能なラベルを取得しておく：

```
gh label list
```

**単一モード:**
```
git log origin/<ベースブランチ>..HEAD --oneline
git diff origin/<ベースブランチ>..HEAD --stat
gh pr create --draft --base <ベースブランチ> --title "<タイトル>" --body "<本文>" --assignee @me --label "<ラベル>"
```
未 push なら先に `git push -u origin HEAD`。

**stacked モード:** Step 2 で絞り込んだ対象フェーズだけを**番号順（`p1 → p2 → ...`）に**作成する。各 PR の base は 1 つ下のフェーズ（`p1` はデフォルトブランチ）：
```
git push -u origin <feature>-pN
git log <base>..<feature>-pN --oneline      # この PR に含まれる差分（前フェーズとの差分）
git diff <base>..<feature>-pN --stat
gh pr create --draft --base <base> --head <feature>-pN \
  --title "<タイトル>" --body "<本文>" --assignee @me --label "<ラベル>"
```
- 各 PR の本文は**そのフェーズの差分だけ**をもとに書く（前フェーズの変更を含めない）
- Summary 冒頭に stacked の位置を明記する（例: `stacked PR 2/3（base: <feature>-p1）`）

**PR 本文テンプレート:**
```
## Summary
（変更の概要を1〜3行で。stacked の場合は位置と base を明記）

## 変更内容
（git diff の結果をもとに変更ファイルと変更内容を箇条書き）

## このPRをマージした後の状態
（tasks.md の `着地状態:` を転記。単一モードでは省略してよい）
```

**`着地状態:` は必ず転記する。** stacked PR はそれ単体では feature が完成しないため、レビュアーが「どこまでできていれば正しいのか」を判断する材料になる。

**言葉づかい（タイトル・本文共通）:** IT・ビジネスの専門用語を避け、読んだ人が知識に関わらず理解できる言葉で書く。
- 避ける例: リファクタリング、マイグレーション、エンドポイント、スキーマ、デプロイ、バリデーション
- 言い換え例: 「コードの整理」「テーブル構造の変更」「APIの受け口」「データの形式」「本番環境への反映」「入力値の確認」

#### 3-2 PR 運用なし（デフォルトブランチへ取り込んで push）

`/impl` はこの運用でもフェーズブランチを切っているので、それを取り込む。フェーズの割り方は変えない（レビューの形が変わるだけ）。

1. `CURRENT` == `DEFAULT`（ブランチを使わず直接コミットした場合）→ マージ不要。手順 3 へ
2. Step 2 で絞り込んだ対象を**番号順に**取り込む（順を飛ばすと差分が入れ子で壊れる）：
   ```
   git checkout "$DEFAULT" && git pull
   git merge --ff-only <対象ブランチ> || git merge --no-ff <対象ブランチ>
   ```
   **コンフリクトが出たらその場で解決せず中断する**（自動解決は差分を壊す）。`git merge --abort` で戻し、中断カードに衝突ファイルを出して人に委ねる
3. push する：
   ```
   git push origin "$DEFAULT"
   ```
   保護ルールで弾かれた場合は、それが想定内か（例: bypass 権限がある旨の記述がある）をプロジェクト `CLAUDE.md` と照らす。判断がつかなければ中断する

### Step 4: 出力

**単体（PR 運用あり）**: 次の完了カードを**コードフェンスで囲まず**プレーンテキストで出力して終了する。カードの前後に作業サマリ・所感・補足を足さない。

✅ draft PR 作成完了
<作成した PR の本数と構成（単一 / stacked N/M）を 1 行>
- <主要な結果 最大 3 行>
🔗 <作成した PR の URL>

要確認:
- <PR 運用の判定が `不明` で `あり` に倒した、など>

次の一手:
▶ CI を監視する：/watch-ci

**単体（PR 運用なし）**: 🔗 行の無い次のカードを出す。PR が無いので `/watch-ci` には進まない（CI が回るならデフォルトブランチ側で回る）。

✅ デフォルトブランチへ反映完了
<どのブランチを <デフォルトブランチ> に取り込んで push したかを 1 行>
- <主要な結果 最大 3 行>

次の一手:
▶ 後片付けする：/cleanup

カードは**やったこと**（`✅` 〜 `🔗`）・**要確認**・**次の一手**の 3 ブロックに分ける。混ぜない。

- やったこと: 一言サマリは 1 行。主要な結果は `- ` の箇条書きで**最大 3 行**（無ければ行ごと省略）。PR 本文の内容はカードに転記しない。🔗 行は **1 PR 1 行**で本数ぶん出す（行数上限は主要な結果にだけ課す）。既存でスキップした PR は URL の後に「（既存）」と添え、stacked の全体像が分かるようにする。
- 要確認: PR 運用の判定が `不明` だった場合は**必ず**（どちらに倒したかと根拠）。ほかに base の取り方やタイトル生成で判断した点があれば添える。無ければブロックごと省略する。
- 次の一手: PR の有無で確定しているので該当する 1 行だけを出す。

**auto**: 完了カードを出さず、次の 1 行の簡易ログだけ残す。次スキルの起動は呼び出し元（orchestrator）が行う。

```
次: /watch-ci
```

**中断時**: 同じブロック構成でヘッダを差し替える（PR 運用ありなら `⚠ draft PR 作成中断`、なしなら `⚠ デフォルトブランチへの反映中断`）。

- やったこと: 一言サマリに中断理由（衝突ファイル・保護ルールでの push 拒否など）。作成できた PR があれば 🔗 行は残す。
- 次の一手: 復帰手順。反映できていないまま `/watch-ci` や `/cleanup` へ進む道は出さない。

## エラー処理
- `gh pr create` が「ブランチが push されていない」→ `git push -u origin <対象ブランチ>` を実行してから再試行する
- `gh pr create` が「head branch is the same as base branch」→ base と head が同じになっていないか確認する（単一モードは Step 3-1 で新ブランチを作る）

## 完了条件
- **PR 運用あり**: 対象フェーズの draft PR を作成（既存ならスキップ）し、URL を報告したら完了
- **PR 運用なし**: 対象フェーズをデフォルトブランチに取り込んで push し、反映内容を報告したら完了

次工程の起動は完了条件に含めない。
