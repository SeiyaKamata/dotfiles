# ユーザーストーリースキル

## 役割
機能要望を PdM・ステークホルダーが読める**ユーザーストーリー形式**でまとめる。技術的な詳細は書かず、**ビジネス価値とユーザー体験**に焦点を当てる。

`/spec` が「開発者向けに要件を EARS 化する」のに対し、こちらは「**開発の外の人に共有する**」ための文書。`/spec` の前段として使える（要件の詳細化はしない）。

## 入出力
- **入力**: 会話で渡された要望 / `.specs/<feature>/requirements.md`（あれば参照）/ `.specs/<feature>/seed.md`（あれば）
- **出力**: `.specs/<feature>/stories.md`

## モード
人がステークホルダーに共有するために起こす文書なので、起動も人が行う。

**途中でユーザーに何も聞かない。** 書き切って完了カードを出し、修正は編集モードでの再実行（`/story <feature>`）で受ける。要望から埋められない点は最も素直な解釈を採り、完了カードの「要確認」に挙げる。

## 進め方

### Step 1: 引数チェック
- `$ARGUMENTS[0]`（feature）が未指定なら「使い方: /story <feature>」を表示して終了

### Step 2: コンテキスト収集とモード判定
読み込む：
- `.specs/<feature>/seed.md`（あれば）— 本文だけを入力にする
- `.specs/<feature>/requirements.md`（あれば）— 既に要件があるならそれを素材にする
- `.specs/<feature>/stories.md`（あれば）

`stories.md` の有無で分岐する：
- **無い → 新規作成モード**: Step 3 へ
- **有る → 編集モード**: 既存をベースに、ユーザーの変更要望に該当する箇所だけを直す

### Step 3: ストーリー化
次の観点を埋める（**技術的な実装方法は書かない**）：

- **誰が使うか**: ユーザーの役割・属性
- **何をしたいか**: 達成したいゴール
- **なぜ必要か**: ビジネス上の価値・背景
- **完了の基準**: どうなれば「できた」と言えるか

要望に書かれていない点は止まらずに最も素直な解釈を採り、Step 5 の「要確認」に挙げる。

### Step 4: 書き出し
次のフォーマットで `.specs/<feature>/stories.md` に書く（ディレクトリが無ければ作成する）。

```markdown
# ユーザーストーリー: [機能名]

## ストーリー

### [ストーリー名]
**As a** [ユーザーの役割],
**I want** [やりたいこと],
**so that** [得られる価値・目的].

**受け入れ条件:**
- [ ] [条件1]
- [ ] [条件2]

**優先度:** 高 / 中 / 低
**スコープ:** 今回含む / 将来対応

---

### [ストーリー名2]
...
```

書き出しの時点で次を満たす：
- 各ストーリーが **As a / I want / so that** の 3 要素を備えている
- 受け入れ条件が**ユーザーから見て観測できる**（内部実装の状態を条件にしない）
- 技術的な実装方法（FW・DB・API 名）が混入していない
- 優先度とスコープが全ストーリーに付いている

### Step 5: 出力

次の完了カードを、コードフェンス自体は出さずに中身だけそのまま出力して終了する。
カードの前後に作業サマリ・所感・補足を足さない。

```markdown
### ユーザーストーリー作成完了
<何本のストーリーをまとめたかを 1 行>
- <主要な結果 最大 3 行>

生成物: `.specs/<feature>/stories.md`

### 要確認
- <要望に根拠が無く、こちらの判断で決めた点>（該当: <ストーリー名>）

### 次の一手
- 要件に落とす: `/spec <feature>`
- ストーリーを直す: `/story <feature>`（編集モードで再実行）
```

カードは**やったこと**・**要確認**・**次の一手**の 3 ブロックに分ける。混ぜない。

- やったこと: 一言サマリは 1 行。主要な結果は `- ` の箇条書きで**最大 3 行**（無ければ行ごと省略）。ストーリー本文・受け入れ条件は stories.md に書き、カードには列挙しない。
- 要確認: 優先度・スコープの割り振りなど、**要望に書かれておらず判断で決めた点**を挙げる。PdM に見せる前に人が直したい箇所がここに出る。無ければブロックごと省略する。
- 次の一手: 2 行とも出す。修正の要否は問わず、ユーザーがどちらかを実行するのを待つ。

**中断時**: ヘッダを `### ユーザーストーリー作成中断` に差し替え、一言サマリに中断理由、次の一手に復帰コマンドを書く（成果物が未生成なら生成物の行は省略する）。

## 完了条件
要望が `.specs/<feature>/stories.md` にユーザーストーリー形式で書き出せたら完了。次工程の起動は完了条件に含めない。
