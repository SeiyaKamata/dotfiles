# 事実確認スキル

## 役割
主張を実物で確かめ、主張ごとに結果と確認の種類を返す。
ロードマップ、spec、過去の PR 説明、コメントの記述は、過去のある時点の情報として扱う。
判断はしない。
何を選ぶかは呼び出し元が決め、このスキルは決める材料の真偽だけを返す。

## 確認の種類

| 種類 | 付ける条件 |
|---|---|
| 実データ | 実行して得た出力、ログ、DB の値、API の応答を見た |
| コード | 実コードを読んだ。`path:行` を添える |
| 未検証 | 読めない、測れない、または手段が無い。理由を添える |

読める、測れるものは自分で読み、測って確認済みにする。
読めない、測れないものに数字を作らず、未検証と書く。

## 判断が割れる点の扱い
ユーザーに質問しない。
確かめ方が複数あるときは、実データ、コードの順に強いほうを採る。
採れなかった確認は未検証として理由を書く。

## 進め方

### Step 1: 主張を並べる
引数か呼び出し元の依頼から、確かめたい主張を 1 行 1 主張に分けて並べる。
主張が無ければ「使い方: /verify <確かめたい主張>」を表示して終了する。

1 行に複数の事実が入っているときは分ける。
確認の種類が行ごとに変わるため。

### Step 2: 確かめ方を決める
主張ごとに、どこを見れば真偽が決まるかを決める。

- 現状の構造、既存の仕組み: Grep と Read で実コードを探す
  - 同じことをする仕組みが既にあるかも探す
- 別 PJ の実装状況: その PJ のデフォルトブランチを読む
  - `mkworktree <bare repo> <リポジトリ名>-<今の worktree のディレクトリ名>` で展開する。同名の worktree があればそれを使う
  - bare repo は、`git rev-parse --git-common-dir` と同じ親ディレクトリの `<リポジトリ名>`。見つからないか bare でなければ未検証にする
- 環境変数、設定値: ローカルと各デプロイ環境の投入先ファイルを実リポジトリで特定する
  - デプロイ定義の有無を確認できなければ未検証にする
- base ブランチの状態: `git fetch` のあと `git log origin/<base>..HEAD` で未マージを見る

### Step 3: 確かめる
主張が独立して 3 件以上あるときは、`Agent` に分けて投げて並列に確かめる。
依頼文には主張、見る場所、報告形式を書き、推測と事実を分けて返すよう指定する。

返ってきた結果は自分で突き合わせる。
報告を鵜呑みにしない。

### Step 4: 報告
主張ごとに次の形で返す。

```
- 主張: <主張>
  結果: 合っている / 食い違う / 確かめられない
  種類: 実データ / コード <path:行> / 未検証
  実際: <食い違うときの実物の姿。未検証のときはその理由>
```

末尾に件数を書く。
合っている N 件、食い違う N 件、未検証 N 件。

食い違いが 1 件でもあれば、その主張を前提にした判断を呼び出し元が見直す必要がある旨を 1 行添える。
