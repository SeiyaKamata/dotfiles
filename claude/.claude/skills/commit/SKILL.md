# コミットスキル

## 役割
変更内容を確認し、`committer` エージェントにコミット分割からコミット実行までを委譲し、結果を報告する。

## 入出力
- **入力**: 作業ツリーの変更。
  `git status` / `git diff`
- **出力**: コミット。
  **ファイル成果物は持たない**ので完了カードに生成物の行は出さない

`/commit` は **push しない**。
`committer` も行わない。

## 対話方針
コミットして完了カードを出す。
コミットすべきでないファイルが混ざっていると判定したときだけ、Step 2 でユーザーに確認する。

## 進め方
各 Step は順番に実行する。
**完了ゲート**を通過するまで次へ進まない。

### Step 1: ブランチチェック

**コミットの可否を判断するのはこの Step だけ。**
`committer` はブランチの状態を理由にコミットを見送らないので、ここで通した判断は後段で覆らない。
逆に、ここで止めなければそのままコミットされる。

```
CURRENT=$(git branch --show-current)
DEFAULT=$(git symbolic-ref --short refs/remotes/origin/HEAD 2>/dev/null); DEFAULT=${DEFAULT##*/}
[ -z "$DEFAULT" ] && { git remote set-head origin --auto >/dev/null; DEFAULT=$(git symbolic-ref --short refs/remotes/origin/HEAD); DEFAULT=${DEFAULT##*/}; }
```

`sed` / `awk` を使わないのは、パイプの補助コマンドが権限の allowlist に無く承認待ちで止まるため。
デフォルトブランチは `origin/HEAD` から引き、未設定のときだけ `set-head --auto` で 1 度張り直す。

判定：

- `CURRENT` が空（detached HEAD）→ 警告へ
- リモートでマージ済み（下記がマッチ）→ 警告へ
  ```
  git fetch origin
  [ "$CURRENT" != "$DEFAULT" ] && \
    git branch -r --merged "origin/$DEFAULT" --format='%(refname:short)' | grep -qxF "origin/$CURRENT"
  ```
  **`CURRENT` が `DEFAULT` と等しいときはこの判定を走らせない。**
  デフォルトブランチは自分自身にマージ済みで、`git branch -r --merged origin/main` は `origin/main` を含む。
  そのため無条件に走らせるとデフォルトブランチで必ずマッチし、下で意図的に外した判定が裏口から復活する。
- いずれも該当しなければ Step 2 へ

**`CURRENT` が `DEFAULT` と一致することは判定しない。**
デフォルトブランチへのコミットはローカルで可逆な上、可否は repo の運用方針次第で正本は `/sync` にある。
意図的な除外なので、ここに判定を戻さないこと。

**警告文:**
> 現在のブランチ `<CURRENT>` は <マージ済み／detached> の状態です。
> 新しいブランチを切ってからコミットしますか？

- 「はい」→ デフォルトブランチを最新化してから新ブランチを作成し Step 2 へ。
  ブランチ名は変更内容から `<type>/<短い説明>` の形で提案する。
  例: `fix/login-redirect`
  ```
  git checkout "$DEFAULT" && git pull
  git checkout -b <新ブランチ名>
  ```
- 「このまま進める」→ Step 2 へ

**完了ゲート:** ブランチ状態を判定し、必要なら新ブランチを切ったか。

### Step 2: 変更の確認と除外の確定

```
git status
git diff
```

生成物・無関係ファイルなど **コミットすべきでないものが混ざっていないか**を確認する。
混ざっていれば除外リストとして確定する。
**混ざっていると判定したときは委譲せず人間に確認する。**

> 人間が「staged のものだけコミットしたい」と明示した場合は、それを裏返して「staged でないものを除外する」形で除外リストに載せる。
> index の状態そのものを絞り込みの指示として解釈しない。

除外ファイルがあれば、委譲前に作業ツリーから隔離する。

```
git stash push --include-untracked -m "commit: 除外ファイル退避" -- <除外ファイル…>
```

`committer` は自分の `git diff` に映らないファイルを気にしようがないので、これで除外リストを口頭で渡す必要がなくなる。
除外がなければこのコマンドは実行しない。

続けて index を空にする。

```
git reset
```

作業ツリーは変更されず、ステージングだけが解除される。
`git commit` は index の内容を丸ごとコミットするため、計画に含まれないファイルが staged で残っていると 1 件目のコミットに紛れ込む。
`committer` は各コミットで対象ファイルだけを `git add` するので、index が空から始まれば内容を完全に制御できる。

**完了ゲート:** 変更内容を把握し、除外ファイルを stash で隔離し、`git reset` で index を空にしたか。

### Step 3: committer に委譲する

`committer` サブエージェントを起動し、次を渡す:
- ブランチは Step 1 で検証済みで `committer` 側で再判定しないこと、index は空にした旨

`committer` は diff 分析 → コミット分割 → メッセージ生成 → ファイル単位のステージングとコミット実行、まで一貫して行い、実行結果を完了・中断で返す。
**委譲前の人間承認は求めない。**

committer が結果を返したら、Step 2 で除外ファイルを stash していた場合は成功・中断を問わず `git stash pop` で戻す。

**完了ゲート:** committer が実行結果、完了または中断を返し、stash していた除外ファイルを pop し終えたか。

### Step 4: 出力

次の完了カードを、コードフェンス自体は出さずに中身だけそのまま出力して終了する。
カードの前後に作業サマリ・所感・補足を足さない。

```markdown
### コミット完了
<ブランチ名> に <N> 件コミットしました
- <コミット件名 最大 3 行>

### 要確認
- <分割で判断に迷った点>（例: 1 ファイルに 2 系統の変更が混ざったため片方に寄せた）

### 次の一手
- リモートへ反映: `/sync`
- 取り消す: `git reset --soft HEAD~<N>`
```

カードは**やったこと**・**要確認**・**次の一手**の 3 ブロックに分ける。
混ぜない。

- やったこと: 一言サマリは 1 行。
  主要な結果はコミット件名を `- ` の箇条書きで**最大 3 行**。
  4 件以上あるときは重要度上位 3 件だけ。
  diff の詳細は git log に寄せ、カードには列挙しない。
  commit はファイル成果物を持たないので生成物の行は出さない。
- 要確認: `committer` の報告から、分割・帰属で判断が割れた点を挙げる。
  無ければブロックごと省略する。
- 次の一手: `取り消す` 行は**実行済みだが取り返しがつく**ことを伝えるために常に出す。
  `--soft` なので変更内容は index に戻り、失われない。

**中断時**: コミットが途中で失敗したら、ヘッダを `### コミット中断` に差し替える。
この中断カードだけは、区分ごとに件名を列挙してよい。

```markdown
### コミット中断
<中断理由を 1 行>
- 完了: [1] <件名> / [2] <件名> …
- 失敗: [k] <件名> — <理由>
- 未実行: [k+1] <件名> …

### 次の一手
- 復帰: `/commit`（残っている変更から計画し直す）
- 取り消す: `git reset --soft HEAD~<完了件数>`
```

**完了ゲート:** カード、または簡易ログを出力したか。

## 完了条件
除外を確定したうえで対象の変更がすべてコミットされ、結果を報告したら完了。
次工程の起動は完了条件に含めない。
