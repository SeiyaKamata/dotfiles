# コミット

## 役割
変更内容を確認し、`committer` エージェントにコミット分割からコミット実行までを委譲し、結果を報告する。

## 自走モード（`auto` 引数）
`$ARGUMENTS` に `auto` が含まれる場合、出力形式のみ切り替える（実行内容・実行順序・分割内容は変わらない）。Step 4 で完了カードを出す代わりに、遷移先を示す 1 行の簡易ログだけを残す。

## 進め方
各 Step は順番に実行する。末尾の完了ゲートを通過するまで次へ進まない。

---

## Step 1: ブランチチェック

**コミットの可否を判断するのはこの Step だけ。** `committer` はブランチの状態を理由にコミットを
見送らないので、ここで通した判断は後段で覆らない（逆に、ここで止めなければそのままコミットされる）。

現在のブランチ名とデフォルトブランチ名を取得する：
```
CURRENT=$(git branch --show-current)
DEFAULT=$(git remote show origin | sed -n 's/.*HEAD branch: //p')
```

判定：
- `CURRENT` が空（detached HEAD）→ 警告へ
- リモートでマージ済み（下記がマッチ）→ 警告へ
  ```
  git fetch origin
  [ "$CURRENT" != "$DEFAULT" ] && \
    git branch -r --merged "origin/$DEFAULT" | sed 's/^[ *]*//' | grep -xF "origin/$CURRENT"
  ```
  **`CURRENT` が `DEFAULT` と等しいときはこの判定を走らせない。** デフォルトブランチは自分自身に
  マージ済みなので（`git branch -r --merged origin/main` は `origin/main` を含む）、無条件に走らせると
  デフォルトブランチで必ずマッチし、下で意図的に外した判定が裏口から復活する。
- いずれも該当しなければ Step 2 へ

**`CURRENT` が `DEFAULT` と一致することは判定しない**（意図的な除外。ここに判定を戻さないこと）。
理由は 2 つ。デフォルトブランチへのコミットは**ローカルで可逆**で（完了カードの
`git reset --soft HEAD~<N>` で戻せる）、危険が現実化するのは push の瞬間だが `/commit` は push
しない（`committer` も `git push` を行わない）。そしてデフォルトブランチへ直接コミットしてよいかは
**repo の運用方針**であって、`/commit` はその方針を知る層にない（判定の正本は `/tasks`
「PR 運用の有無の判定」で、材料はプロジェクト `CLAUDE.md`）。push 側の押さえは `/create-pr` の
Step 1.5 が持つ。

上の 2 つは運用方針に依らず機械的に危険なケースだけを残している（detached HEAD はコミットが
到達不能になる、マージ済みブランチは閉じた PR に積む）。

**警告文:**
> 現在のブランチ `<CURRENT>` は <マージ済み／detached> の状態です。新しいブランチを切ってからコミットしますか？

- 「はい」→ デフォルトブランチを最新化してから新ブランチを作成し Step 2 へ
  ```
  git checkout "$DEFAULT" && git pull
  git checkout -b <新ブランチ名>
  ```
  ブランチ名は変更内容から `<type>/<短い説明>`（例: `fix/login-redirect`）の形で提案する。
- 「このまま進める」→ Step 2 へ

**完了ゲート:** ブランチ状態を判定し、必要なら新ブランチを切ったか。

---

## Step 2: 変更ファイルを確認し、除外を確定して index を空にする

```
git status
git diff
```

生成物・秘密情報・無関係ファイルなど **コミットすべきでないものが混ざっていないか** を確認する。混ざっていれば、それを除外リストとして確定する（コミットすべきでないファイルが混ざっていると判定したときは、委譲せず人間に確認する）。

> 人間が「staged のものだけコミットしたい」と明示した場合は、それを裏返して「staged でないものを除外する」形で除外リストに載せる。index の状態そのものを絞り込みの指示として解釈しない。

除外を確定したら、委譲前に index を空にする。

```
git reset
```

作業ツリーは変更されず、ステージングだけが解除される。`git commit` は index の内容を丸ごとコミットするため、計画に含まれないファイルが staged で残っていると 1 件目のコミットに紛れ込む。`committer` は各コミットで対象ファイルだけを `git add` するので、index が空から始まれば内容を完全に制御できる。

**完了ゲート:** 変更内容を把握し、除外ファイルを確定し、`git reset` で index を空にしたか。

---

## Step 3: committer に委譲する

`committer` サブエージェントを起動し、次を渡す:
- 除外ファイルの一覧（なければ「なし」）
- ブランチは Step 1 で検証済み（`committer` 側で再判定しない）・index は空にした旨

`committer` は diff 分析 → コミット分割 → メッセージ生成 → ファイル単位のステージングとコミット実行、まで一貫して行い、実行結果（完了/中断）を返す。委譲前の人間承認は求めない。

委譲中は表示が止まるので、出力規律に従って開始時に 1 行だけ出す。

**完了ゲート:** committer が実行結果（完了または中断）を返したか。

---

## Step 4: 結果を報告する

`committer` から返った実行結果に基づき、末尾「完了カード」のブロックを出力して終了する。

**単一 PR / スタック PR のどちらでも、コミット直後に `/create-pr` へ進む。** スタック PR 運用でも、**フェーズごとにその 1 本の PR を出して CI green + CodeRabbit 解決まで閉じてから次フェーズを積む**（全フェーズを積んでから一斉作成はしない）。理由は orchestrator の「なぜフェーズごとに PR を出すのか」を参照。`/create-pr` は既に PR があるフェーズをスキップする冪等な作りなので、重複作成の心配はいらない。

**完了ゲート:** 完了カードを出力したか。

## 出力規律
実行中の逐次ナレーション（「〜します」「〜しました」）は出さない（ツール実行はターミナルに表示されるため二重になる）。ただし committer へ委譲して表示が止まる区間の開始時だけ、次の 1 行を出す（1 区間 1 回）。

⏳ commit: committer で計画とコミットを実行中…

## 完了カード
Step 4 で、次の完了カードを**コードフェンスで囲まず**プレーンテキストで出力して終了する。カードの前後に作業サマリ・所感・補足を足さない。次スキルは自動起動せずユーザーの実行を待つ。

- commit は**ファイル成果物を持たない**ので 📄 行は出さない。コミット件数と件名を主要な結果に載せる（4 件以上あるときは重要度上位 3 件だけ出す）。
- 一言サマリは 1 行。主要な結果は `- ` の箇条書きで**最大 3 行**。diff の詳細は git log に寄せ、カードには列挙しない。

✅ コミット完了
<ブランチ名> に <N> 件コミットしました
- <コミット件名 最大 3 行>
▶ 取り消す：git reset --soft HEAD~<N>
▶ OK：git push してから /create-pr

`▶ 取り消す` 行は「実行済みだが取り返しがつく」ことを伝える。`--soft` なので変更内容は index に戻り、失われない。

コミットが途中で失敗して中断したときは、同じ構成でヘッダを `⚠ コミット中断` に差し替え、次の形式で出す（各区分の中では件名を列挙してよい）。

⚠ コミット中断
<中断理由を 1 行>
- 完了: [1] <件名> / [2] <件名> …
- 失敗: [k] <件名> — <理由>
- 未実行: [k+1] <件名> …
▶ 取り消す：git reset --soft HEAD~<完了件数>
▶ 復帰：/commit（残っている変更から計画し直す）

自律モード（起動引数に `auto` を含む）では完了カードを出さず、遷移先を 1 行の簡易ログだけ残す（例: `次: /create-pr`）。次スキルの起動は呼び出し元（orchestrator）が行う。
