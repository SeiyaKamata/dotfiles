# 図解資料スキル

## 役割
図解資料を `.specs/zukai-<題材>.html` に書き出すときに、過去の経験から積んだ注意点を守らせる。
図の描き方やページ設計の一般論は組み込みの指示に従い、このスキルは自分固有の注意点だけを持つ。
組み込みの指示と衝突したら、このスキルの注意点を優先する。
ローカルファイルにするのは、手で直す回数が多く、Notion や PR に載せる形も後から選べるため。

## 判断が割れる点の扱い
途中でユーザーに質問も承認要求もしない。
図解の対象と粒度は、引数の本文と会話の文脈から自分で確定し、完了カードで事後報告する。

## 注意点
- コードの変更を扱うときは before と after を並べて載せる
  - 差分だけでは何がどう変わったか読み手が復元できないため
- 変更や設計には理由を書く
  - 結果だけだと、読み手が妥当性を判断できないため

## 進め方

### Step 1: 材料の特定

- 引数に図解したい内容があれば、それを材料にする
- 引数が無ければ会話の文脈から、直前に話していた変更や設計を材料にする
- どちらにも材料が無ければ「使い方: /zukai [図解したい内容]」を表示して終了

### Step 2: 資料の作成

「注意点」をすべて満たす構成を決め、`.specs/zukai-<題材>.html` に書き出す。
題材は図解の対象を kebab-case で 2〜4 語にする。
図解が複数要るときは題材ごとに別ファイルにする。
同名のファイルがあれば、別の図解なら区別がつく題材にし、同じ図解の作り直しなら上書きする。

### Step 3: 出力

次のカードを、コードフェンス自体は出さずに中身だけ出力して終了する。
中断時は見出しを `### 図解作成中断` にし、1 行目に中断理由を書き、生成物の行は省く。

```markdown
### 図解作成完了
<何を図解したかを 1 行>

生成物:
- `.specs/zukai-<題材1>.html`
- `.specs/zukai-<題材2>.html`
```
