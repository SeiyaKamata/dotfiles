# セッション再開スキル

## 役割
中断した開発セッションの状態を調べ、どのスキルから再開すべきかをコマンド付きで提案する。
状態調査は **`recoverer` サブエージェントに委譲**する（git/gh/.specs の調査出力をメインコンテキストに載せないため）。あなたは feature の決定（対話）と結果提示を担う。

## 引数
- `$ARGUMENTS`: feature名（省略可。省略時は `.specs/` の一覧から選ばせる）

## 進め方

### Step 1: feature名を決定する（対話・inline）

`$ARGUMENTS` が指定されていればそれを使用する。

未指定なら `.specs/` 以下のディレクトリを列挙する：

```
ls -1 .specs/ 2>/dev/null
```

- 候補が1件もない場合: 「`.specs/` にディレクトリが見つかりません。orchestrator を使った開発中ではないかもしれません」と伝えて終了する
- 候補がある場合: 番号付きで提示し、選ばせる：

```
.specs/ 以下のディレクトリが見つかりました：

1: foo-feature
2: bar-feature

番号で選んでください（その他: 手入力）:
```

### Step 2: recoverer へ委譲
feature が決まったら `recoverer` サブエージェントを起動し、feature 名を渡す。recoverer が `.specs/<feature>` の中身・git・PR/CI の状態を調べ、工程を推定して「状態の要約＋再開コマンドの提案」を返す。

### Step 3: 結果提示
recoverer が返した状態要約と再開コマンド提案を、末尾の `## 完了カード` の形でユーザーに提示する。推定コマンドは自動起動せず、ユーザーの実行を待つ。

## 完了条件
- 再開コマンドを提案したら完了
- 人間がコマンドを実行するかどうかはこのスキルの範囲外（実行しない）

## 出力規律
実行中の逐次ナレーション（「〜します」「〜しました」）は出さない（ツール実行はターミナルに表示されるため二重になる）。ただし recoverer へ委譲して表示が止まる区間の開始時だけ、次の 1 行を出す（1 区間 1 回）。Step 1 の feature 選択はユーザーへの質問なのでこの制限の対象外。

⏳ recover: recoverer で再開ポイントを調査中…

## 完了カード
再開ポイントの推定が済んだら、次の完了カードを**コードフェンスで囲まず**プレーンテキストで出力して終了する。カードの前後に作業サマリ・所感・補足を足さない。推定したコマンドは自動起動せずユーザーの実行を待つ。

- recover は**ファイル成果物を持たない**ので 📄 行は出さない。今どこまで進んでいるか（最終工程・ブランチ・PR/CI の状態）を主要な結果に載せる。
- 一言サマリは 1 行。主要な結果は `- ` の箇条書きで**最大 3 行**（無ければ行ごと省略）。recoverer の調査ログはカードに転記しない。
- ▶ 行は推定工程が一意に確定するなら 1 行。複数の工程にまたがって曖昧なら条件付きで 2〜3 行に増やして人間に選ばせる（行数上限は主要な結果にだけ課す）。

✅ 再開ポイント特定
<推定した工程と根拠を 1 行>
- <主要な結果 最大 3 行>
▶ OK：<推定した再開コマンド（例: /impl <feature>）>
▶ OK（条件A）：<コマンドA>
▶ OK（条件B）：<コマンドB>

完了条件を満たせずに終了するときは、同じ構成でヘッダを `⚠ 再開ポイント特定中断` に差し替え、一言サマリに中断理由（`.specs/` が無い・状態から工程を推定できないなど）、▶ 行に復帰コマンドを書く。
